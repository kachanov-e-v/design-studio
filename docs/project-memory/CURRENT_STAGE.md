# Current Stage

Preview host server shipped: the extension serves demo.html and an injected proxy for user dev apps over http://127.0.0.1 (PreviewHostServer), because vscode-resource subresource frames inside iframe-based webviews failed the ds:ping/ds:pong handshake ("Runtime not detected"). Root cause of runtime failing everywhere: preview-runtime bundle was built with --format=esm (invalid as a plain <script>); fixed to IIFE with global name DesignStudioRuntime, verified by verify-build. Inline demo runtime is regenerated by npm run build (inline:demo step). User-entered http(s) URLs are wrapped through the local proxy with <base>, root-absolute attribute/CSS rewriting, a service worker for JS-issued fetches, and a websocket tunnel for HMR. Protocol validated end-to-end in headless Chrome (handshake, ds:select on click, ds:apply-style) both for inline demo and proxied app without any user code changes. Automated checks pass: typecheck, lint, tests, build. Manual VS Code Extension Development Host verification remains.
