# Диагностика

## После авторизации приложение снова показывает страницу входа

Preview iframe загружает приложение с временного локального адреса расширения. Dev-сервер приложения видит запросы через прокси; исходные `Domain` и `Path` из `Set-Cookie` не соответствовали адресу preview-хоста и могли терять сессию на следующем маршруте. В актуальном preview-хосте `Domain` удаляется, `Path` устанавливается в `/`, а cookies продолжают передаваться upstream.

Также проверьте для Next.js 16+ dev-серверов: если приложение в превью выглядит отрисованным, но клик по кнопкам отправляет обычную GET-форму (страница просто перезагружается), а DevTools показывает повторяющиеся `WebSocket connection to 'ws://127.0.0.1:PORT/_next/hmr' failed` — гидратация React не связалась с SSR-разметкой из-за отключённого HMR-WebSocket. Preview-хост переписывает `Origin` WS-апгрейда на адрес upstream, чтобы дев-сервер Next принимал соединение; устаревшая сборка расширения пересылала адрес превью и получала отказ. Пересоберите расширение (`npm run build`) и перезагрузите Extension Development Host. Альтернативный фикс на стороне проекта — перечислить адрес превью в `allowedDevOrigins` в `next.config.ts` приложения (Next печатает подсказку об этом в терминал dev-сервера).

Проверьте:

1. В toolbar выбран именно запущенный dev-сервер текущего проекта.
2. Пересобрано/перезагружено расширение после обновления исходников; в тестовом Extension Development Host выполните **Developer: Reload Window**.
3. После входа адрес в preview соответствует маршруту приложения, а не внутреннему `/proxy/...` URL.
4. В **Вывод** → **Design Studio Preview** нет `502`; эта запись означает, что локальный preview-хост не смог подключиться к upstream. Проверьте, что `npm run dev` всё ещё работает и порт совпадает.
5. В DevTools страницы проверьте ответ входа и наличие session cookie, если проблема сохраняется. Атрибуты приложения `Secure` и `SameSite` сохраняются; авторизацию и её политику задаёт само приложение.

Запросы вида `GET /proxy/http:/localhost:3000/login 404` соответствуют старому/нормализованному формату proxy URL. Текущий интерфейс использует обычные route paths приложения для страниц и структурированный `/proxy/http/host/...` адрес для явных proxy-запросов. Если такое сообщение продолжает появляться, проверьте, что запущена актуальная собранная версия расширения, затем перезагрузите Extension Development Host.

## Режим правки включён, но элементы не подсвечиваются или не выбираются

1. Убедитесь, что кнопка режима показывает **Просмотр** (то есть режим правки включён) и строка превью показывает, что runtime подключён и правка включена.
2. Наводите курсор на видимый элемент. Обычный клик выбирает его во включённом режиме правки; активация контрола при этом не происходит.
3. Выберите **Демо**, чтобы отделить проблему приложения от проблемы установки runtime.
4. При статусе ожидания/ошибки откройте **Developer: Open Webview Developer Tools** и проверьте доступность preview/runtime. Отладочный лог у runtime отсутствует: маркер успешной сборки — `initDesignStudioRuntime` (используется `npm run build` → `verify-build`).
5. Выполните `npm run build`, перезапустите Extension Development Host. Runtime и валидатор протокола должны быть собраны из одних исходников.
6. Проверьте Console и Output на ошибки загрузки, CSP, сети и версию протокола.

Runtime внедряется в HTML-ответ. Политика безопасности, добавленная самим приложением через `<meta http-equiv="Content-Security-Policy">`, особенности нестандартной навигации или ошибки загрузки страницы могут блокировать script даже при работающем upstream. Смотрите сообщения DevTools превью.

Исправленная ошибка payload: runtime посылает вычисленные CSS-свойства по всему `STYLE_PROPS`; прежний лимит в 64 поля превышал фактический payload и валидатор отбрасывал hover/select-сообщения. Текущая проверка согласована с длиной `STYLE_PROPS`.

## Proxy возвращает 403 «Destination not supported in preview»

Preview-хост ходит только на loopback-адреса (`localhost`, `127.0.0.0/8`, `::1`, `0.0.0.0` и поддомены `.localhost`). Приватные сети (`192.168.x`, `10.x`, `172.16–31.x`), link-local/metadata (`169.254.169.254`) и внешние сайты недоступны по дизайну — это защита от SSRF. Тело ответа содержит точную причину (`scheme`/`credentials`/`non-loopback`) и затронутый URL; детали также в канале **Design Studio Preview** (`[proxy] blocked ... target: ...`). Redirect'ы приложения на внешние адреса (например, OAuth-провайдер) прокси не переписывает — фрейм открывает их нативно; после внешней авторизации вернитесь на локальный URL приложения в адресной строке preview. Если приложение тянет ресурсы с другого хоста, проксируйте их на стороне dev-сервера или запустите бэкенд на `127.0.0.1`.

## Не активна кнопка «Скопировать инструкцию»

Кнопка активируется, когда выбран элемент, введено непустое пожелание или есть правки в сессии. Пробелы без текста не считаются пожеланием. Если поле заполнено, но кнопка всё ещё неактивна, проверьте, что интерфейс загружен полностью и что используется актуальная webview-сборка.

## Переход по произвольному маршруту возвращает 404

В адресной строке превью используйте локальный путь, например `/dfgdfvdzfv`, либо полный URL выбранного dev-сервера. Убедитесь, что адрес относится к тому же origin/порту, который указан как активный. Next.js сам определяет, существует ли маршрут; Design Studio передаёт этот route upstream и не создаёт страницу, которой нет в приложении.

Если открылась страница 404 приложения, прокси работает, а маршрут не существует. Если показано `Not found` от preview-хоста, проверьте выбранный сервер, runtime-статус и лог в канале **Design Studio Preview**.

## Значения известных сообщений

| Сообщение | Значение |
| --- | --- |
| `Build artifacts verified: extension.js, index.html, demo.html, runtime.js, protocol.js` | Сборочный скрипт успешно проверил созданные артефакты. Это не ошибка. |
| `npm notice New major version of npm available` | Информационное уведомление npm о новой версии. Само по себе не влияет на сборку или preview. |
| Next.js `Cross origin request detected from 127.0.0.1 to /_next/*` / `allowedDevOrigins` | Предупреждение dev-сервера Next.js о происхождении запроса. Оно не означает автоматически ошибку входа или маршрута. Если текущая версия Next.js требует явную настройку, настройте `allowedDevOrigins` в `next.config` тестового приложения согласно документации именно этой версии. |
| `GET /proxy/http:/localhost:3000/login 404` | Некорректно нормализованный proxy URL старого формата или устаревший frontend/runtime. Текущий маршрут страницы в preview должен выглядеть как `/login`. |
| `502` в канале `Design Studio Preview` | Upstream локальный сервер недоступен либо не ответил за 30 секунд. Проверьте процесс и порт dev-сервера. |
| `403` «Destination not supported in preview» | Цель запроса не прошла loopback-валидацию (SSRF-гейт). Другие сети и внешние хосты недоступны из preview по дизайну — см. раздел выше. |
| `Runtime protocol mismatch` | Webview и iframe используют разные версии runtime. Пересоберите расширение целиком и перезапустите Extension Development Host. |

## Логин в приложении падает с `error=Configuration` (NextAuth)

NextAuth v5 отвечает редиректом на `/auth/error?error=Configuration`, когда сам запрос падает с серверной ошибкой внутри приложения (недоступная база данных, отсутствие/несовпадение `AUTH_URL`/`NEXTAUTH_URL`, секрет, провайдеры без env-значений). Проверка простая — воспроизведите POST напрямую на dev-сервер **без preview**:

```bash
CSRF=$(curl -s -c /tmp/cj.txt http://localhost:3000/api/auth/csrf | grep -oE '"csrfToken":"[^"]*"' | cut -d'"' -f4)
curl -s -X POST http://localhost:3000/api/auth/callback/credentials -b /tmp/cj.txt \
  -d "csrfToken=$CSRF" -d "email=test@example.dev" -d "password=wrong" \
  -d "callbackUrl=http://localhost:3000/dashboard" -d "json=true"
```

Если ответ содержит `error=Configuration`, проблема в конфигурации самого проекта (env/база/порт), а не в Design Studio. Частые причины: Postgres-контейнер не запущен, а `DATABASE_URL` использует имя сервиса docker-compose (`postgres:5432`) вместо `127.0.0.1:<проброшенный порт>`; `AUTH_URL`/`NEXTAUTH_URL` указывает на другой порт, чем реальный dev-сервер. Логин, который не работает и в обычном браузере, не может быть исправлен превью — сначала почините запуск приложения.

## CSS-правка не сохраняется в проект

Прямое сохранение поддерживает CSS-файлы и работает только при единственном точном совпадении. Случаи без исходного правила, несколько одинаковых селекторов, недоступные браузеру внешние таблицы стилей или неразрешённый CSS Module могут быть неоднозначны. Правка остаётся в preview; экспортируйте инструкцию для ручного изменения JSX/TSX/CSS выбранным ИИ-агентом.
