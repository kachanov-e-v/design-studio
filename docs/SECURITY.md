# Безопасность и обработка данных

## Сетевые запросы и preview

- Preview HTTP-сервер расширения слушает `127.0.0.1` на временном порту.
- В качестве upstream принимаются только HTTP/HTTPS адреса localhost: `localhost`, поддомены `.localhost`, loopback-адреса и `0.0.0.0`. Расширение предназначено для локального dev-сервера, а не для просмотра произвольных внешних сайтов.
- Запросы iframe к активному localhost-серверу проксируются локальным процессом расширения. Браузерные cookies и необходимые app-router/server-action заголовки передаются upstream.
- `Domain` из ответа `Set-Cookie` удаляется, `Path` приводится к `/`, остальные атрибуты cookies сохраняются. Это нужно, чтобы локальная preview-сессия работала между маршрутами. Cookies обрабатывает браузер на временном локальном origin и preview-прокси; Design Studio не использует их для внешних сервисов.
- Размер тела upstream-запроса ограничен 10 МБ, ответа — 20 МБ, таймаут ответа — 30 секунд.
- Для iframe preview удаляет некоторые response headers проекта, которые блокируют встраивание или вмешиваются в проксирование (в том числе `X-Frame-Options` и CSP response headers). Исходные конфигурационные файлы проекта не меняются. Поэтому используйте режим с доверенным локальным проектом; содержимое страниц проекта исполняется в iframe.

## Файлы workspace

- Проектные файлы отдаёт только локальный HTTP-хост и ограничивает пути корнем workspace.
- Поиск компонентов и CSS идёт только в открытом workspace. Для копирования исходника допускаются файлы `.tsx`, `.jsx`, `.ts`, `.js`, `.mts`, `.mjs`, `.mdx` размером не более 300 КБ.
- CSS сохраняется через VS Code `WorkspaceEdit`, только если найдено одно однозначное правило. При неопределённом/множественном совпадении запись не производится.

## Буфер обмена и ИИ

- Сгенерированная инструкция и исходник компонента копируются в системный буфер только по нажатию пользователя соответствующей кнопки.
- Расширение не вызывает MCP, агентские расширения, чаты, сетевые ИИ API и не отправляет текст автоматически.
- После копирования пользователь сам решает, куда вставлять содержимое. В инструкции могут быть текст страницы, классы, CSS, имена компонентов, пути файлов, фрагменты source hints и пользовательское пожелание.

## Webview и диагностика

- Локальная панель использует Content Security Policy и разрешает локальные ресурсы расширения.
- Обмен между страницей и webview выполняется через версионированный `postMessage` протокол с `sessionId`; сообщения проверяются по структуре и лимитам размера/количества.
- Канал **Design Studio Preview** предназначен для диагностики и записывает маршрут запроса, URL upstream, статус ответа и redirect metadata. При диагностике не публикуйте логи без проверки: query-параметры URL могут содержать данные вашего локального приложения.

## Граница доверия

Подключайте только собственный localhost dev-сервер и доверенный workspace. Preview исполняет HTML и JavaScript приложения внутри iframe, а для отображения может ослаблять некоторые HTTP-ограничения ответа приложения. Внешний ИИ-сервис получает данные только если пользователь сам вставит скопированный текст в этот сервис.
