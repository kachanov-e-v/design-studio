# Архитектура

Design Studio — самостоятельное расширение VS Code. Оно не подключается к агентам, чатам или ИИ API. Все интеграции с ИИ выполняются через текст: расширение формирует инструкцию или исходный контекст и копирует его в системный буфер обмена после нажатия пользователем кнопки.

## Компоненты

| Путь | Ответственность |
| --- | --- |
| `src/extension` | Команда открытия, жизненный цикл webview, выбор проекта и сервера, обмен сообщениями с интерфейсом. |
| `src/domain` | Модель изменений и формирование инструкции на русском или английском. |
| `src/infrastructure/preview` | Обнаружение localhost dev-сервера, временный HTTP-хост превью, маршрутизация запросов и внедрение runtime. |
| `src/infrastructure/source-analysis` | Поиск вероятных исходников элемента и разрешение React/bundler-путей. |
| `src/infrastructure/ai` | Экспорт инструкции и исходника компонента в буфер обмена. Здесь нет вызовов ИИ или агентских API. |
| `src/infrastructure/persistence` | Поиск CSS-правила и сохранение однозначной CSS-правки через `WorkspaceEdit`. |
| `packages/preview-runtime` | Runtime, сбор сведений об элементе, выбор, визуальное редактирование и типизированный протокол сообщений. |
| `webview` | Минималистичный интерфейс React, инспектор, превью, история правок и локализация RU/EN. |
| `webview/public` | Собранные браузерные файлы runtime и протокола, копируемые при сборке. |

## Жизненный цикл превью

1. Расширение создаёт локальный preview HTTP-сервер на случайном порту, привязанный к `127.0.0.1`.
2. Адрес dev-сервера определяется по сценариям `package.json` и проверяется локально. Сервер можно выбрать вручную. Основной сценарий — Next.js; обнаруживаются также Vite, Astro, Webpack и статические HTTP-серверы.
3. Приложение загружается в iframe из локального preview-хоста. Для dev-сервера расширение сохраняет активный upstream origin (sticky target), поэтому адреса приложения остаются обычными маршрутами, например `/login` и `/board/123`, а не транспортными `/proxy/...`.
4. Маршруты и запросы iframe проксируются к выбранному localhost-серверу. Если браузер отправил абсолютный URL через маршрут `/proxy/http/host/...`, прокси разбирает его; для обычных путей цель определяется из активного сервера или Referer.
5. В ответ HTML добавляются `<base>`, `runtime.js` и регистрация service worker. Относительные пути приложения остаются привязаны к текущему маршруту; root-absolute CSS URL перенаправляются через прокси. Service worker передаёт same-origin запросы приложения через активный upstream.
6. Прокси пересылает cookies, заголовки Next.js App Router/RSC и данные server actions. `Origin` и `Referer` направляются на исходный upstream origin. Redirect `Location` и заголовок `x-action-redirect` переписываются так, чтобы внутренние переходы оставались на preview-хосте; ответ server action сохраняется.
7. Атрибут `Domain` в upstream `Set-Cookie` удаляется, а `Path` устанавливается в `/`. Другие атрибуты, включая `HttpOnly`, `Secure` и `SameSite`, сохраняются. Так cookie авторизации доступна на маршрутах локального preview-хоста, а браузер отправляет её обратно через прокси на dev-сервер.

Для статического предпросмотра HTML-файла из workspace расширение внедряет runtime напрямую и обслуживает файлы только внутри корня открытого проекта.

## Выбор и редактирование элементов

Runtime внедряется в страницу и работает внутри iframe. Webview и runtime обмениваются сообщениями `postMessage` по протоколу из `packages/preview-runtime/src/protocol.ts`. Сначала выполняется handshake с версией протокола, nonce и ID сессии; сообщения с другой версией или сессией отклоняются. Входящие payload проверяются перед использованием.

При включённом режиме правки runtime обрабатывает наведение и клик: подсветка следует за прямоугольником элемента, обычный клик выбирает элемент. Интерактивные элементы (ссылки, кнопки, поля, элементы с ARIA-ролями) требуют **Alt+клика**. Двойной клик по неинтерактивному элементу начинает inline-редактирование текста; Enter или потеря фокуса применяют изменение, Escape отменяет его.

Для выбранного DOM-элемента runtime передаёт:

- селектор элемента и ограниченный набор альтернативных селекторов;
- тег, положение, размеры, классы, текст и вычисленные CSS-свойства;
- совпадающие правила доступных внешних таблиц стилей;
- обнаружение Tailwind;
- React owner chain с путями/строками, когда dev runtime приложения их предоставляет.

Runtime может применить в текущем DOM текстовую, классовую, структурную или CSS-правку. Структурные операции: удалить, дублировать, переместить вверх/вниз. Эта сессия предпросмотра не является записью в JSX/TSX. После навигации или перезагрузки страницы правки DOM обычно сбрасываются.

Важное соответствие протокола: runtime отправляет полный набор вычисленных CSS-свойств `STYLE_PROPS`, а валидатор разрешает ровно этот набор по длине. В противном случае payload выбора отклоняется, и hover/select сообщения не доходят до инспектора.

## Инструкция и правка исходника

Инструкция формируется из языка интерфейса, пожелания пользователя, выбранного элемента (если он есть), доступной информации о React-компонентах, source hints и списка изменений со значениями до и после. Повторные изменения одного свойства/текста/набора классов сворачиваются до финального значения, сохраняя начальное значение. Структурные операции остаются отдельными записями.

Детали компонента определяются по React dev runtime и подсказкам поиска по workspace. Это best-effort сведения: проверяйте путь и файл в кодовом агенте перед редактированием. Кнопка **Копировать исходник** копирует один найденный файл кода размером не более 300 КБ. Пользователь сам выбирает агент и вставляет текст.

Прямое сохранение доступно для CSS: сначала ищется ровно одно подходящее правило в CSS-файлах проекта, затем используются source map и эвристики для CSS Modules. При отсутствии точного результата или при неоднозначности расширение не записывает файл; изменённое значение остаётся в текущем preview DOM и может быть перенесено через инструкцию.

## Лимиты и ограничения

- dev-сервер должен быть локальным (`localhost`, `*.localhost`, loopback IP); используются только HTTP и HTTPS;
- тело проксируемого запроса ограничено 10 МБ, ответ — 20 МБ, ожидание upstream — 30 секунд;
- payload runtime ограничивает длину строк и количество селекторов, классов, правил и компонентов;
- правила из cross-origin CSS или `<style>` могут быть недоступны для источникового анализа браузера;
- сведения о React-компонентах зависят от dev-сборки и доступности Fiber owner metadata;
- текст, классы и структурные операции передаются в инструкции, а автоматически сохраняется только найденный CSS;
- внешние redirect приложения могут привести к адресу вне локального preview.
