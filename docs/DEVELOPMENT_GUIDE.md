# Разработка

## Требования

- VS Code `1.105` или новее;
- Node.js и npm;
- открытый workspace Next.js для основного сценария предпросмотра;
- локально запущенный dev-сервер приложения.

## Установка зависимостей и сборка

Из корня репозитория:

```bash
npm install
npm run typecheck
npm run lint
npm run build
```

`npm run build` выполняет последовательные шаги:

1. собирает Node.js-расширение в `dist/extension.js`;
2. собирает браузерный runtime из `packages/preview-runtime`;
3. копирует собранные runtime и protocol в `webview/public`;
4. собирает интерфейс webview в `dist/webview`;
5. встраивает runtime в демо-страницу;
6. проверяет наличие непустых артефактов, загрузку ресурсов webview и браузерный формат runtime.

Успешная последняя строка сборки имеет вид `Build artifacts verified: extension.js, index.html, demo.html, runtime.js, protocol.js`. Это сообщение сборочного скрипта о пройденной проверке файлов.

Для отдельной разработки runtime:

```bash
npm --prefix packages/preview-runtime install
npm --prefix packages/preview-runtime run build
```

После изменения protocol/runtime для работы из собранного расширения нужно выполнить общий `npm run build`: он обновляет копии в `webview/public` и `dist/webview`.

## Запуск Extension Development Host

1. Откройте репозиторий расширения в VS Code.
2. Нажмите F5.
3. В появившемся Extension Development Host откройте папку тестового Next.js-проекта.
4. Запустите приложение (`npm run dev`).
5. Выполните команду **Дизайн-студия: Открыть дизайн-студию**.

Адреса предлагаются по сценариям разработки из `package.json` и проверяются TCP/HTTP-запросами. Для адресов `localhost` дополнительно проверяется, похож ли ответ на нужный проект. Если автопоиск не сработал, используйте **Сервер** и введите `http://localhost:3000` вручную. К локальному маршруту можно перейти, введя `/login`; для полной навигации доступны кнопки назад, вперёд и обновление.

Выпадающий список **Проект** позволяет открыть демо, проектный HTML-файл или подключиться к dev-серверу. Демо удобно использовать отдельно от авторизации и конфигурации тестового приложения.

## Режим правки

Кнопка **Правка: вкл./выкл.** — единственный переключатель режима.

- наведите курсор на страницу: текущий элемент подсветится;
- кликните обычный элемент: инспектор покажет его параметры;
- любой элемент выбирайте обычным кликом во включённом режиме правки: активация контрола при этом не происходит;
- дважды кликните неинтерактивный элемент, чтобы отредактировать его текст прямо в странице; Enter или потеря фокуса применяют изменение, Escape отменяет;
- в инспекторе редактируйте текст, классы, CSS-свойства, а также удаляйте, дублируйте и перемещайте элементы;
- поле внизу принимает пожелание и позволяет копировать инструкцию даже без выбранного элемента.

Превью показывает состояние подключения runtime. Для выбора нужен статус **Подключено** и включённый режим правки. Изменения относятся к текущей загруженной странице; это визуальная рабочая сессия, а не автоматическое редактирование JSX/TSX.

## Перенос правок в исходники

**Скопировать инструкцию** создаёт текст на выбранном языке. В него входят область и цель изменений, контекст выбранного элемента, вероятные компоненты и файлы, релевантные стили, Tailwind-подсказка и применённые значения до/после. Если элемент не выбран, инструкция остаётся общей для страницы или проекта.

**Копировать исходник** в инспекторе копирует контекст найденного файла компонента размером до 300 КБ. Вставьте инструкцию или исходник в чат любого ИИ-агента; расширение не открывает чат и не отправляет данные автоматически.

**Сохранить стили** записывает CSS-свойство в исходный CSS-файл, только если правило установлено без неоднозначности. Для CSS Modules сначала может применяться source map. Если CSS-правило не разрешилось в один файл и селектор, кнопка покажет ошибку; используйте экспорт инструкции.

## Настройка языка

Переключатель **RU / EN** находится в правом конце toolbar. Язык сохраняется в глобальном состоянии VS Code. Он меняет интерфейс и язык инструкции; HTML-приложение, открытое в iframe, не переводится.

## Отладка

- Webview Developer Tools: команда VS Code **Developer: Open Webview Developer Tools**.
- Сетевые сообщения preview-прокси: панель **Вывод** → канал **Design Studio Preview**. Записи показывают время, метод, локальный target и HTTP status.
- Preview сообщает runtime-статус: подключение, таймаут, несовпадение протокола, ошибка или заблокированная загрузка.
- Runtime выводит `Design Studio runtime loaded` в консоль страницы при успешном запуске.
- Если менялись JS/TS файлы расширения или runtime, пересоберите проект и перезапустите Extension Development Host, чтобы не использовать старые артефакты.

Симптомы авторизации, маршрутизации, выбора и распространённых сообщений Next.js/npm разобраны в [руководстве по диагностике](TROUBLESHOOTING.md).

## Протокол runtime

Контракты сообщений и `ElementPayload` находятся в `packages/preview-runtime/src/protocol.ts`. Сообщения имеют версию протокола, передаваемые между iframe и webview `sessionId`, а операции редактирования — `requestId`. Webview принимает только сообщения активной сессии; runtime валидирует входящие операции. При добавлении типа сообщения обновляйте обе стороны протокола, проверки и собранные браузерные файлы через `npm run build`.

Основные типы: handshake (`ds:ping` / `ds:pong`), переключение режима, hover/select, применение CSS и операций над элементом, подтверждения изменений и навигация. Объём payload ограничен валидатором, чтобы игнорировать неожиданно большие или некорректные данные.
