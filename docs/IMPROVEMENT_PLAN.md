## Оставшиеся корневые ограничения

### RC1. Правки живут только в DOM и памяти сессии

- Текст/структура/классы применяются к живому DOM iframe; ближайший React-ререндер
  или HMR затирает их. Стили частично переживают reload через StylePersistenceAdapter,
  остальные виды правок — нет.
- Журнал правок (`edits` в App.tsx) не переживает перезагрузку webview/окна VS Code.
- Undo есть только у структурных операций (снапшоты runtime, лимит 50); стили/текст
  отменить нельзя, кроме как вручную.
- План (EPIC IMP-A): реестр применённых правок + повторное применение после
  `ds:runtime-ready`; персист журнала через workspaceState расширения; undo для
  style/text на базе журнала (before/after уже есть).

### RC2. CSP страницы снимается полностью

- proxy-html.ts снимает CSP-заголовки и meta, иначе инлайн-runtime не выполнится.
  Это ослабляет защиту пользовательской страницы на время превью.
- План (IMP-B): инжекция runtime внешним скриптом (`/__ds-runtime.js` уже отдаётся
  хостом) с nonce; сохранять исходный CSP, добавляя nonce/источник хоста;
  fallback — текущее снятие с явным предупреждением в UI. Задокументировать
  ограничение cookie jar браузера (изоляция сделана на уровне прокси).

### RC3. Компоненты видны только в React dev mode

- fiber.ts читает `__reactFiber$` — в production-сборках данных нет; остаётся
  SourceHintFinder (эвристика по токенам). Vue/Svelte/angular не поддерживаются.
- План (IMP-C): source-map-based детекция (bundler source maps → файл/строка
  компонента) как fallback; интерфейс ComponentDetector для будущих фреймворков.

### RC4. Кэш сканов — TTL, не индекс

- ComponentResolver кэширует результаты на 30 с; холодный скан всё ещё читает
  до 3000 файлов. Инвалидация по времени, а не по изменениям файлов.
- План (IMP-C): общий индекс исходников (файл → определения/токены) с
  fs.watch-инвалидацией; переиспользовать в SourceHintFinder, ComponentResolver,
  PromptExportService.

### RC5. Нет e2e-проверки в реальном окружении

- Все тесты — jsdom/unit. Поведение в живом VS Code (webview sandbox, троттлинг
  rAF, реальный iframe cross-origin) не покрыто; именно там жили FIX-01..08.
- План (IMP-D): смоук-сценарий вручную по чек-листу (фиксировать в docs); затем
  e2e через @vscode/test-electron + playwright против fixtures/static-site и
  тестового React-приложения; порог покрытия в CI.

### RC6. Документация отстаёт от протокола

- docs/AI_HANDOFF.md и IMPLEMENTATION_PLAN.md описывают v3/v4; актуален v8
  (ds:mark, ds:undo/ds:undone). SECURITY.md не отражает ADS/SSRF/cookie-фиксы.

## Риски и зависимости

- IMP-A reapply должен быть идемпотентным и не конфликтовать с React:
  применять только к существующим селекторам, пропускать исчезнувшие,
  не трогать элементы вне body; снапшоты undo хранить в журнале, а не только в runtime.
- IMP-B: nonce должен ротироваться на сессию; страницы с `strict-dynamic`
  требуют отдельного теста; fallback обязан быть видимым пользователю.
- IMP-C source maps: читать только локальные maps (loopback/файловая система),
  не ходить во внешнюю сеть — иначе новый SSRF-вектор.
- Любой новый тип сообщения → bump PROTOCOL_VERSION + запись в CHANGELOG (IMP-F).
